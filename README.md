# Oficio

> **The verification-first agent engine for real-world trades.**
> The LLM talks; deterministic engines calculate; evals prove it.

[![CI](https://github.com/brayans7/oficio/actions/workflows/ci.yml/badge.svg)](https://github.com/brayans7/oficio/actions)

Oficio turns a natural conversation with a customer into a **provably correct remodeling quote**. It is built on one uncompromising rule: **the language model never computes a price.** The agent extracts what the customer wants — with literal evidence (`source_quote`) for every line — and a deterministic pricing engine, driven by a versioned price book derived from a **real construction business** (anonymized), calculates to the cent.

## Why this exists

Most AI demos ask you to trust them. Oficio is designed to be *verified* instead:

| Claim | Proof (runs in CI) |
|---|---|
| Prices are exact | 30 golden quotes reproduced to the cent |
| The agent doesn't invent | Extraction eval: 100 labeled cases, **zero-invented-values gate** |
| Injection doesn't work | 20-attack security suite, 0 allowed through |
| Costs are controlled | Fail-closed pricing, per-request cost telemetry, daily budget |

*(Eval tables in this README are generated by `python -m oficio.evals.report` — never written by hand.)*

## Architecture

```
src/oficio/
  core/    # deterministic: schemas, price book, quote engine — pure, no LLM imports
  agent/   # conversational: extraction w/ evidence, model routing, cost meter, guardrails
  evals/   # labeled datasets, runner, report generator — the public proof
data/
  pricebook.v1.json   # anonymized real-world price book (labor + materials)
```

Hard boundary: `agent/` imports `core/`. Never the reverse.

## Design decisions (deliberate)

- **Neuro-symbolic split** — LLMs are excellent at understanding and terrible at arithmetic accountability. The engine owns every number.
- **Evidence or it didn't happen** — every quote line carries `source_quote`, the literal customer text that justifies it. A line without evidence is an eval failure, not a feature.
- **Fail-closed everywhere** — unknown item → `needs_info` (never estimate); model without a price entry → exception (never $0); missing secrets → refuse to start.
- **No database in v1** — a JSON price book and JSONL traces are enough for the MVP. Deliberately out of scope: payments, auth, multi-tenancy, scheduling, a second vertical.

## Provenance

The price book is derived from the live operations of a family remodeling business, with names removed and prices scaled by an undisclosed factor with per-item jitter — realistic ratios, protected business. The anonymization pipeline is private by design and enforced by a leak-gate test in CI.
